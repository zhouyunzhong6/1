# 第 2 章 Physical Intelligence（π）：一群 Google 老兵如何定义"开源 VLA 的标准答案"

> **一句话定位**：全球最具影响力的纯"机器人大脑"创业公司。π 系列（π0 → π0-FAST → π0.5 → π0.6/π*0.6 → π0.7）几乎每一代都成为行业的"参考实现"：π0 确立了"VLM + 流匹配动作专家"架构，π0.5 确立了"异构数据协同训练 + 高层语义子任务"的开放世界泛化范式，π*0.6 把强化学习引入大 VLA 的真实部署，π0.7 则把"可引导（steerable）"和"组合泛化"带到台前。openpi 开源仓库让 π 成为全球 VLA 研究与创业公司的事实基线（包括大量中国公司的对标对象）。

## 1. 故事的开端：从 Google 走出来的"梦之队"

2023 年，Google 的机器人团队拥有当时世界上最好的 VLA（RT-2）、最大的多机构数据集（OXE）、最强的语言模型。但这个团队也面临大公司的典型困境：机器人研究在 Google 内部的优先级远低于 Gemini，Everyday Robots 在 2023 年初被裁撤，硬件车队缩减。

Karol Hausman 与 Brian Ichter 等人判断：**机器人领域的"GPT 时刻"需要一个只做机器人大脑、能够快速试错的组织**。他们拉上了深度强化学习与机器人学习领域最有声望的两位教授——Sergey Levine（Berkeley，QT-Opt、SAC、离线 RL 的奠基人之一）与 Chelsea Finn（斯坦福，MAML、ALOHA/Mobile ALOHA 的指导者之一）——于 2024 年成立了 Physical Intelligence。公司名的缩写"π"既是物理智能（Physical Intelligence）的首字母，也暗含"通用常数"的寓意。

π 的战略可以概括为三句话：

1. **只做大脑，不做本体**——用尽可能多的不同机器人收集数据，逼模型学会"跨本体"；
2. **数据为王，但要"多样"**——相比单纯堆小时数，更看重环境、任务、本体的多样性；
3. **开源基线，闭源前沿**——把上一代模型开源给社区（openpi），用最新一代保持领先。

## 2. 代表作一：π0（2024.10）——"VLM + 流匹配动作专家"范式的确立

> 论文：*π0: A Vision-Language-Action Flow Model for General Robot Control*（Black, Brown, Driess, ... , Levine, Finn 等，arXiv 2410.24164）

### 2.1 它要解决的问题

RT-2/OpenVLA 一类"离散 token 化"的 VLA 有两个硬伤：

- **频率太低**：自回归一个 token 一个 token 地生成动作，7B 模型往往只有几 Hz，做不了叠衣服这种需要连续、柔顺、高频调整的任务；
- **精度太差**：256 桶的量化在双臂灵巧操作中误差积累明显。

另一方面，ACT、Diffusion Policy 这类"小模型 + 连续动作生成"方法虽然能做高频灵巧操作，却没有语义泛化能力，只能"一个任务训一个模型"。

π0 的目标是**两者兼得**：既继承 VLM 的语义与常识，又能以 50 Hz 输出连续、平滑、精确的动作块。

### 2.2 架构：一个 VLM + 一个"动作专家"

```
           图像（最多 3 路相机）   语言指令       本体状态 q_t     加噪动作块 A_t^τ（50 步）
                 │                  │               │                    │
          SigLIP 视觉编码器      Gemma 分词         线性投影             线性投影 + 流匹配时间步 τ 嵌入
                 │                  │               │                    │
                 └──────┬───────────┘               └─────────┬──────────┘
                        ▼                                     ▼
        ┌──────────────────────────────┐      ┌──────────────────────────────┐
        │  VLM 主干（PaliGemma 3B）       │◄────►│  动作专家（约 3 亿参数）         │
        │  权重 A（处理图像与文本 token）  │ 共享  │  权重 B（处理状态与动作 token）   │
        └──────────────────────────────┘ 自注意力└──────────────────────────────┘
                                                              │
                                                              ▼
                                          预测向量场 v_θ(A_t^τ, o_t) → 积分 10 步得到动作块
```

关键设计：

1. **VLM 主干**：PaliGemma（SigLIP 约 4 亿参数视觉编码器 + Gemma 2B 语言模型），总约 30 亿参数，用互联网规模预训练提供语义知识。
2. **动作专家（Action Expert）**：一个约 3 亿参数、结构与 Gemma 类似但更窄的 Transformer，专门处理本体状态 token 与动作 token。它与 VLM 主干**不是串联的两个模型，而是同一个 Transformer 的两组权重**——类似"混合专家（MoE）"：图像/文本 token 走 VLM 的权重，状态/动作 token 走动作专家的权重，但所有 token 在每一层**共享自注意力**。整体约 33 亿参数。
3. **分块因果注意力（blockwise causal attention）**：token 被分成三块——[图像+文本]、[本体状态]、[加噪动作]。前一块不能看到后一块（保证 VLM 前缀可被 KV 缓存复用），块内部双向注意力。这样在推理时，图像和文本只需前向一次，后续 10 步流匹配积分只需重算动作专家部分。
4. **流匹配（Flow Matching）**：动作专家不是直接回归动作，而是学习一个"从噪声流向真实动作"的速度场。训练时，取真实动作块 A，采样噪声 ε 与时间 τ，构造 A^τ = τA + (1−τ)ε，让网络预测 (ε − A) 方向的速度；推理时从纯噪声出发用欧拉法积分 10 步得到动作块。流匹配相比 DDPM 式扩散更简洁、步数更少。论文还用了一个偏向"高噪声时间步"的 Beta 分布采样 τ，强调学习"从粗到细"的动作结构。
5. **动作块（Action Chunking）**：一次输出未来 H=50 步动作，对应 50 Hz 控制下约 1 秒。这一思想来自 ALOHA/ACT，可显著降低高频控制中的复合误差。

### 2.3 数据："π 数据集 + OXE"的混合配方

- **π 自有数据**：约 1 万小时的灵巧操作示范，覆盖 **7 种机器人构型、68 类任务**——包括单臂 UR5e、双臂 UR5e、Franka、双臂 Trossen、双臂 ARX、移动 Trossen、移动 Fibocom 等。
- **开源数据**：OXE "Magic Soup" 子集（含 DROID、Bridge 等），提供更大的视觉与场景多样性。
- **采样权重**：对每个"任务-机器人"组合按样本量的 n^0.43 次方加权，避免大任务淹没小任务。
- **动作空间统一**：不同机器人的动作/状态维度不同，统一零填充到最大维度（18 维），由模型自己学会"这台机器人用前几维"。

### 2.4 训练配方："预训练 + 后训练"，像训练 LLM 一样训练机器人

π0 论文最有影响力的观点之一，是**把 LLM 的"预训练-后训练"范式明确引入机器人**：

- **预训练**：在多样但质量参差的海量数据上训练，让模型学到广泛的能力，**尤其是从错误中恢复的行为**（因为低质量数据里充满了失误与纠正）；
- **后训练（post-training）**：在少量高质量、精心整理的特定任务数据上微调，让模型学会"流畅、高效、可靠"地完成复杂任务。

作者的类比是：只在高质量数据上训练的模型"不知道犯错后该怎么办"；只在多样数据上训练的模型"不够熟练"。两阶段结合，才能既稳又强。

### 2.5 实验结果

- **开箱即用（零样本）**：在叠衬衫、清理桌面（bussing）、装袋、把食品放进烤面包机等任务上，π0 显著超过 OpenVLA（7B，离散 token）与 Octo（93M，扩散头）；
- **语言跟随**：与不使用 VLM 初始化的 π0-small 对比，VLM 初始化带来明显的指令跟随提升；
- **后训练的复杂任务**：从烘干机取衣服 → 放入篮子 → 带到桌边 → 逐件叠好；清理餐桌；组装纸箱；装鸡蛋。洗衣折叠是当时公认的"机器人图灵测试"之一，π0 的演示视频在行业内引发轰动。
- **与小模型对比**：在后训练的灵巧任务上，π0 也超过 ACT、Diffusion Policy 等专门方法，说明大模型预训练在灵巧任务上同样有正迁移。

### 2.6 openpi：改变行业格局的开源

2025 年 2 月，PI 开源 **openpi** 仓库，发布 π0 与 π0-FAST 的基础权重、在 ALOHA/DROID/LIBERO 上的微调示例和训练代码（最初基于 JAX，后续支持 PyTorch），2025 年 9 月又开源了 π0.5。开源的影响是深远的：

- 全球无数实验室与创业公司（包括大量中国公司）以 π0/π0.5 为起点做微调或二次开发；
- 第三方评测平台（如 RoboChallenge、RoboArena）把 π0/π0.5 作为"必比基线"——中国的千寻 Spirit v1.5 在 2026 年 1 月登顶 RoboChallenge 时，宣传重点正是"超越 π0.5"；
- Hugging Face LeRobot 把 π0 移植到 PyTorch，使其进入更广泛的开源生态。

### 2.7 π0-FAST：另一条"离散"支线（2025.01）

π0 发布三个月后，PI 发表了 *FAST: Efficient Action Tokenization for Vision-Language-Action Models*。它重新审视"离散 token 化"路线，问题是：**为什么自回归 VLA 在高频灵巧任务上训不动？** 答案是：高频动作在相邻时间步高度相关，逐步、逐维的 256 桶 token 让"预测下一个 token"几乎变成"复制上一个 token"，学习信号极弱。

FAST（Frequency-space Action Sequence Tokenization）的做法借鉴了 JPEG 压缩：

1. 对动作块的每个维度做**离散余弦变换（DCT）**，把时间序列转成频率系数；
2. 对系数做缩放与取整量化（高频系数大多变为 0）；
3. 把各维度的系数按"低频在前"交错展平；
4. 用 **BPE（字节对编码）** 压缩成更短的 token 序列。

结果：同样的动作块，token 数大幅减少且每个 token 信息量更高；基于 FAST 的自回归 π0-FAST 在训练速度上比扩散版 π0 快约 5 倍，性能相当；PI 还发布了在 100 万条真实轨迹上训练的通用 tokenizer **FAST+**。代价是推理时需要自回归解码较多 token，速度慢于流匹配。

FAST 的真正价值在后面才显现：它成为 π0.5 预训练阶段和"知识隔离（KI）"训练的关键组件。

## 3. 代表作二：π0.5（2025.04）——走进从未见过的家

> 论文：*π0.5: a Vision-Language-Action Model with Open-World Generalization*（arXiv 2504.16054）；配套：*Knowledge Insulating Vision-Language-Action Models: Train Fast, Run Fast, Generalize Better*（2025.05）

### 3.1 它要解决的问题

π0 很强，但它是在"见过的环境里"强。如果把机器人放进一个**从未见过的真实家庭**——陌生的厨房布局、陌生的碗碟、陌生的光照——还能工作吗？这就是"开放世界泛化（open-world generalization）"，也是家用机器人的根本门槛。

PI 的假设是：**泛化来自知识迁移，而知识必须来自多种来源**。光靠"在目标场景采集数据"是不可扩展的；必须让模型从各种各样的数据中"拼凑"出在新环境中所需的能力。

### 3.2 数据：一份"异构数据菜谱"

π0.5 的训练数据由以下几类组成（这是论文最核心的贡献之一）：

| 数据类型 | 内容 | 作用 |
|---|---|---|
| **MM**：移动操作数据 | 约 100 个真实家庭中、移动双臂机器人做家务的示范（约 400 小时） | 目标场景的直接经验 |
| **ME**：多环境非移动数据 | 单臂/双臂静态机器人在多种家庭环境中的数据 | 环境多样性 |
| **CE**：跨本体实验室数据 | π0 时代的各种实验室数据 + OXE | 技能多样性 |
| **HL**：高层子任务标注 | 把长任务切分成"捡起盘子""打开抽屉"等语义子任务并标注 | 学会"下一步该做什么" |
| **WD**：网络数据 | 图像描述、VQA、物体检测 | 语义与常识 |
| **VI**：口头指令数据 | 人类实时口头"教练"机器人完成任务（"把那个碗放进水槽"） | 学会听从细粒度指令 |

一个惊人的事实是：**真正来自"移动机器人在家庭中"的数据，只占第一阶段训练样本的极小比例**（论文报告约 2.4%）；绝大部分能力来自其他来源的迁移。消融实验显示，去掉 ME 或 CE 数据会显著降低在新家庭中的表现，去掉网络数据则主要损害对"陌生物体"的识别与理解。

### 3.3 模型与训练：两阶段 + 层级推理

π0.5 的结构延续 π0（VLM + 动作专家），但训练与推理方式升级：

**两阶段训练**：
1. **预训练阶段**：所有数据（包括动作）都以**离散 token** 的形式训练——动作用 FAST 编码。这让整个模型像训练 VLM 一样高效，且能把机器人数据与网络数据无缝混合。
2. **后训练阶段**：加入**流匹配动作专家**，学习输出连续动作块，以支持高频精细控制；同时继续保留部分离散 token 训练与网络数据，防止遗忘。

**层级推理（同一个模型的两次调用）**：
```
观察（图像）+ 高层指令："把厨房收拾干净"
            │
            ▼  第一步：模型以文本形式输出"高层子任务"
     "pick up the plate"（捡起盘子）
            │
            ▼  第二步：同一个模型，以子任务为条件，用动作专家输出 50 步连续动作块
     [a_t, a_{t+1}, …, a_{t+49}]
```
这与 DeepMind 的"ER + VLA 两个模型"不同，π0.5 是**一个模型扮演两个角色**——高层推理与低层控制共享同一套权重，因此高层推理天然"知道"低层能做什么。这种设计被很多后续工作沿用（例如智元 GO-1 的 ViLLA、星海图 G0 等都以不同形式实现了"一个/两个模型的快慢协作"）。

### 3.4 知识隔离（Knowledge Insulation, KI）

π0.5 发布一个月后，PI 发表了 KI 论文，回答了一个微妙但重要的问题：**为什么给 VLM 接上一个随机初始化的动作专家后，VLM 原有的语言与语义能力会"被污染"？**

原因是：在联合训练初期，动作专家的梯度质量很差，这些梯度回传进 VLM 主干，破坏了它在互联网上学到的表征。

KI 的方案：
- 用 **FAST 离散动作 token** 训练 VLM 主干（让 VLM 自己学到"动作的表征"）；
- 用**流匹配**训练动作专家；
- **在动作专家到 VLM 之间加"梯度截断（stop-gradient）"**：动作专家可以读取 VLM 的表征，但它的梯度不回传给 VLM；
- 同时继续用网络数据联合训练 VLM。

效果是"训练快（离散 token 训练高效）、运行快（推理用流匹配连续动作）、泛化好（VLM 知识不被破坏）"，即论文标题所说的三件事。这一配方后来成为 π0.6 及很多开源 VLA 的默认做法。

### 3.5 实验结果

- **在三个从未见过的旧金山真实家庭中**，π0.5 驱动的移动双臂机器人完成了收拾厨房（把碗碟放进水槽、擦台面）、整理卧室（叠被子、把衣服放进洗衣篮、捡起地上的物品）等**10–15 分钟级别的长时程任务**；
- **环境数量的缩放规律**：训练环境数量从少到多（直至约 100 个）时，在全新环境上的表现持续上升，在约 100 个环境时，接近"直接在测试环境上训练过的模型"的表现。这条曲线是"数据多样性比数据量更重要"的最有力证据之一；
- **语言跟随**：对"把勺子放进抽屉""把衬衫放在床上"之类的细粒度指令的跟随率显著高于 π0。

### 3.6 局限

PI 在论文与博客中坦承：π0.5 在新家庭中仍然会犯错——抓不稳、走错位置、忘记任务进度（模型没有长期记忆）、在面对极不熟悉的物体时失败。这些问题分别由后续的 π*0.6（RL 自我改进）、MEM（记忆）、π0.7（可引导与组合泛化）去回答。

## 4. 代表作三：π0.7（2026.04）——可引导的通用模型与"涌现能力"

> 论文：*π0.7: a Steerable Generalist Robotic Foundation Model with Emergent Capabilities*（arXiv 2604.15483，2026-04-16）；官方博客 *π0.7: a Steerable Model with Emergent Capabilities*。
> 前置技术：*π\*0.6: a VLA That Learns From Experience*（arXiv 2511.14759，2025.11）；*MEM: Multi-Scale Embodied Memory for Vision Language Action Models*（arXiv 2603.03596，2026.03）。

要读懂 π0.7，必须先理解它的两块"基石"：π*0.6 的 RECAP（从经验中学习）和 MEM（多尺度记忆）。

### 4.1 前置一：π0.6 与 π*0.6 / RECAP（2025.11）——让 VLA 从自己的经验中变强

**π0.6 底座**：VLM 主干升级到约 40 亿参数（Gemma 3 4B 级别），动作专家扩大到约 8.6 亿参数，并采用 KI 式训练。

**问题**：模仿学习的天花板是"示范者的水平"，而且模型无法从部署中的失败里学习。真实工业场景要求的是"连续运行数小时不出错 + 越干越快"。

**RECAP（RL with Experience and Corrections via Advantage-conditioned Policies）** 的流程：

```
① 预训练：在示范数据上训练 VLA，同时训练一个"价值函数"（分布式价值，预测任务还要多久完成/能否成功）
        ↓
② 部署：机器人自主执行任务，收集"自主经验"；人类在机器人出错时远程接管纠正（"干预/纠错数据"）
        ↓
③ 用价值函数给每段数据计算"优势（advantage）"：这一步比平均水平好还是差？
        ↓
④ 训练"优势条件化策略"：把二值化的优势指示符 I_t（"这一步是好的/不好的"）作为输入条件喂给 VLA
        ↓
⑤ 推理时：始终告诉 VLA "请执行优势为正的动作" → 得到优于平均示范水平的策略
        ↓
   回到②，迭代多轮
```

RECAP 巧妙之处在于：**它不需要 PPO 那样的在线策略梯度**（对大模型和真机都极不稳定），而是把 RL 转化为"条件化监督学习"——好的数据和坏的数据都用，但打上"好/坏"的标签；推理时只要"好"的那一半行为。这与 LLM 领域的 "Decision Transformer / 奖励条件化" 一脉相承，也和 classifier-free guidance 的思想相通。

**价值函数**的直观表现：当机器人在推进任务时，价值预测上升；卡住或犯错时，价值走平甚至下降。这本身就是一个可以用于监控的"任务进度计"。

**结果**：在制作意式浓缩咖啡、在陌生家庭中叠各种衣物、在工厂中组装包装纸箱三类任务上，π*0.6 在最难的任务上**吞吐量提升一倍以上、失败率显著下降**；媒体报道其能连续一整天制作咖啡、长时间不间断叠衣服、在真实工厂中组装纸箱，成功率在 90% 以上。

### 4.2 前置二：MEM（2026.03）——给机器人装上"多尺度记忆"

π0.5 的一大失败模式是"忘事"：收拾厨房到一半，忘了哪些柜子已经检查过。MEM（Multi-Scale Embodied Memory）给 VLA 设计了两种记忆：

- **短时视频记忆**：用视频编码器把过去若干帧（多相机、多时间步）压缩成紧凑表征，让模型感知"刚才发生了什么"（例如物体被遮挡前在哪里）；
- **长时文本记忆**：模型用自然语言写下并更新"已完成事项摘要"（例如"已经擦完台面，水槽里还有两个碗"），作为长期记忆随时读取。

视频负责"细节与动态"，文本负责"长程与抽象"——这种"多尺度"设计让基于 π0.6 的机器人能完成长达约 15 分钟的整厨清洁等任务。

### 4.3 π0.7 的核心思想：可引导（Steerable）

π0.7 的核心洞察是：**机器人数据的"质量"是高度异质的**——同样是叠衣服，有人做得快、有人做得慢；有的成功、有的失败；有的用关节控制、有的用末端控制。传统 VLA 把这些数据一视同仁地混在一起训练，结果模型学到的是"平均水平"甚至更差。

π0.7 的回答：**把"这段数据是怎么做的"也作为输入告诉模型**，让模型学会"在条件 X 下应该如何行动"；推理时，用户通过指定条件来"引导（steer）"模型的行为。

### 4.4 架构与输入

π0.7 约 50 亿参数，由三部分组成：

| 组件 | 规模 | 作用 |
|---|---|---|
| VLM 主干 | 约 40 亿参数 | 理解图像、语言与各类条件 |
| MEM 式视频历史编码器 | — | 压缩多相机、多帧历史 |
| 动作专家 | 约 8.6 亿参数 | 流匹配输出连续动作块 |

**输入的"多模态提示（multi-modal prompt）"**：
1. **相机图像**：最多 4 路相机，每路最多 6 帧历史；
2. **语言**：任务指令、子任务指令，乃至人类的"口头教练"（verbal coaching）；
3. **子目标图像（subgoal images）**：最多 3 张"当前子步骤结束时场景应该是什么样"的图像——由一个**以 BAGEL（字节跳动开源的统一多模态模型）初始化的世界模型**异步生成（二手资料称约 140 亿参数、约每 4 秒或意图变化时刷新一次）；
4. **回合元数据（episode metadata）**：描述这段行为"如何完成"的标签，如速度、质量等；
5. **控制模式标签**：告诉模型输出关节空间还是末端空间的动作。

**训练技巧——条件随机丢弃**：训练时每种条件都会被随机丢弃（例如子目标图像只出现在约 25% 的样本中，元数据约 15% 的时间被整体丢弃），使得推理时任意子集的条件都能工作；推理时还可以在元数据上使用 **classifier-free guidance（CFG）**，进一步放大"更快""更高质量"等期望行为。

### 4.5 关键发现

1. **"元数据让数据缩放重新成立"**：论文报告，不带元数据的 π0.7 在更大、质量混杂的数据上训练时，性能**反而可能下降**；带元数据的 π0.7 则随数据增加**持续提升**。这是一个对整个行业都很重要的结论——它意味着"收更多数据"必须配合"更好的数据标注/条件化"，否则规模化会被低质量数据拖累。
2. **组合泛化（compositional generalization）**：π0.7 能完成训练数据中从未出现的"任务 × 本体"组合。最有代表性的例子是：在 UR5e 机械臂上叠衬衫——训练集中没有任何 UR5e 叠衬衫的数据——仅通过人类的口头分步指导就完成了任务。这说明模型把"叠衬衫的知识"（来自其他本体）和"UR5e 的运动能力"（来自其他任务）组合了起来。
3. **通才追平 RL 专才**：论文称，π0.7 **开箱即用**（无任务专属后训练）即可在论文涉及的所有任务上与 π\*0.6 的 **RL 专用策略**相竞争——包括意式浓缩咖啡制作、纸箱组装、叠衣服——并且在**多样化叠衣服**与**纸箱组装**上的**吞吐量甚至高于 RL 专才**；同时 PI 也坦承，在专才训练过的大量重复任务上，专才仍可持平或更好。
4. **跨本体的"口头教练"**：二手解读称，π0.7 在 UR5e 上零样本叠衬衫的成功率约 80%，接近专家遥操作员的约 80.6%（未在论文原文中逐字核实）。

### 4.6 为什么 π0.7 重要

π0.7 标志着 VLA 设计哲学的一个转向：**从"模型输出什么"到"如何给模型下指令"**。语言只是提示的一种；子目标图像、元数据、控制模式、口头教练都是提示。这与 LLM 从"补全模型"走向"指令遵循 + 系统提示"的历程高度相似。它也把世界模型（生成子目标图像）作为"规划器"嵌入到 VLA 的输入端——这是 2026 年"VLA 与世界模型合流"大趋势的一个典型样本。

## 6. 横向对比与身位

**与 DeepMind 的对比**：两者是"同门师兄弟"——PI 的创始团队大多来自 Google RT 系列。区别在于：DeepMind 依托 Gemini 母体，强在推理与语言；PI 依托开源 VLM（PaliGemma/Gemma）做小而精的模型，强在动作质量、数据配方与 RL 后训练。DeepMind 用两个模型分层（ER + VLA），PI 倾向于一个模型兼任高低层（π0.5）并用多模态提示引导（π0.7）。

**与 NVIDIA GR00T 的对比**：GR00T N1 在结构上借鉴了 π0（VLM + DiT 流匹配），但更强调仿真与合成数据（DreamGen、Isaac）；PI 几乎完全依赖真实数据。2026 年 NVIDIA 转向"世界动作模型"（DreamZero/GR00T N2），PI 则把世界模型作为"子目标生成器"接入 π0.7——两者在"世界模型如何进入机器人大脑"上给出了不同答案。

**与中国追赶者的对比**：π0/π0.5 是中国大量 VLA 公司的直接对标物。2026 年 1 月千寻 Spirit v1.5 在 RoboChallenge 上超过 π0.5，说明在"开源上一代"层面，中国团队已经追平；但 π0.7（未开源）所代表的可引导性、组合泛化与 RL 后训练体系，仍是领先的。

**身位**：模型能力全球第一梯队（与 DeepMind、Generalist 并列），学术影响力与开源影响力第一；商业化最慢——截至 2026 年中，公开报道普遍认为其收入极少。

**2026 年 10 月 13 日：Pi API Beta**。多家媒体报道，PI 开放了 **Pi API 测试版**：开发者可以**上传自己的机器人数据、在 PI 托管的算力上微调 Pi 模型，并通过托管推理网关把得到的模型部署到自己的机器人上**；访问需申请、分批开通，尚无公开价目表。关于开放了哪些模型，报道说法不一（有报道称包括 π0、π0.5 等；另有分析指出此次未发布新模型）。这是 PI 从"研究 + 开源"走向"**模型即服务**"的标志性一步，也印证了本章对其"平台化"路径的判断。

## 7. 未来展望与风险

**展望**：
1. **从模型公司到平台公司**：API/微调服务化是自然的下一步，PI 可能成为"机器人界的 OpenAI"——向本体厂商、集成商提供模型与微调服务；
2. **RL 规模化**：RECAP 证明了真机 RL 的可行性，下一步是"车队级"的持续学习——每台部署的机器人都在为模型贡献经验；
3. **世界模型的深度整合**：π0.7 已用世界模型生成子目标，未来可能进一步用世界模型做策略评估与"想象中训练"。

**风险**：
1. **数据护城河**：PI 不做本体、不做部署，数据主要靠自建采集团队与合作伙伴。相比特斯拉、Figure（自有工厂）或 Generalist（数十万小时真实交互）、它石（百万小时人类数据），PI 的数据规模是否足够，存在疑问；
2. **估值压力**：百亿美元级估值需要商业化兑现，而机器人大脑的商业模式（按机器人授权？按 API 调用？）仍未被验证；
3. **开源的"双刃剑"**：openpi 让行业整体进步，也让追赶者快速追平上一代能力。
